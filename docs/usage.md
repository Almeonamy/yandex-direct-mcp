# Сценарии работы

Формулируешь задачу словами — агент сам подбирает вызовы. Ниже: что сказать, что происходит под капотом и на что смотреть.

Точные имена полей и допустимые значения всегда можно уточнить инструментом `direct_reference` и в [справочнике API v5](https://yandex.ru/dev/direct/doc/ru/concepts/about).

## Аналитика

### Куда ушёл бюджет

> «Покажи расход по кампаниям за август, отсортируй по тратам»

```json
{
  "SelectionCriteria": { "DateFrom": "2026-08-01", "DateTo": "2026-08-31" },
  "FieldNames": ["CampaignName", "Impressions", "Clicks", "Cost", "Ctr", "AvgCpc", "Conversions"],
  "ReportName": "campaigns-2026-08",
  "ReportType": "CAMPAIGN_PERFORMANCE_REPORT",
  "DateRangeType": "CUSTOM_DATE",
  "Format": "TSV",
  "IncludeVAT": "YES",
  "IncludeDiscount": "NO"
}
```

`ReportName` должен быть уникальным — иначе Директ вернёт ранее сформированный отчёт с теми же данными.

### Фразы, которые тратят впустую

> «Найди ключевые фразы, которые за последние 30 дней потратили больше 3000 рублей и не дали ни одной конверсии»

Отчёт `CRITERIA_PERFORMANCE_REPORT` с полями `CampaignName`, `Criterion`, `Cost`, `Clicks`, `Conversions`, фильтрация — уже на стороне агента. Если конверсии нужны по конкретной цели Метрики, в ReportDefinition добавляются `Goals` и `AttributionModels`.

### Мусор в поисковых запросах

> «Собери поисковые запросы за месяц, покажи, по каким мы платим зря, и предложи минус-слова»

`SEARCH_QUERY_PERFORMANCE_REPORT` с полями `Query`, `CampaignName`, `Cost`, `Clicks`, `Conversions`. Дальше агент группирует запросы, показывает кандидатов в минус-слова и добавляет их после подтверждения.

### Сравнение периодов

> «Сравни август с июлем по кампаниям: где выросла цена конверсии»

Два отчёта за разные периоды и сведение по `CampaignName`.

## Управление

### Ставки

> «Подними ставку на 15% там, где CPA ниже 800 рублей, и срежь на 20% там, где выше 2500»

```json
{ "Bids": [ { "KeywordId": 12345678, "Bid": 34500000 } ] }
```

Ставки — в микроединицах: `34500000` = 34,5 ₽. Изменения идут пакетами, каждый пакет — с подтверждением.

### Остановка и запуск

> «Останови кампании, которые за неделю потратили больше 50 000 без заказов»

```json
{ "SelectionCriteria": { "Ids": [123456, 123457] } }
```

Методы `suspend` и `resume` сервиса `campaigns`; для групп и объявлений — те же методы соответствующих сервисов.

### Минус-слова

> «Добавь в кампанию 123456 минус-слова: бесплатно, своими руками, авито»

Через `update` кампании или группы — в зависимости от того, на каком уровне нужны минус-слова.

### Создание структуры с нуля

> «Собери поисковую кампанию под кроссовки Nike: группы по моделям, по 5 фраз в группе, объявления с ценой в заголовке»

Порядок вызовов: `campaigns.add` → `adgroups.add` → `keywords.add` → `ads.add` → `ads.moderate`. Агент показывает структуру до отправки — правится на словах, пока не устроит.

## Семантика

> «Проверь, есть ли спрос по этим 40 фразам»

`keywordsresearch.hasSearchVolume` — показывает, есть ли у фразы поисковый объём в заданном регионе.

Справочники (`dictionaries.get`) отдают коды регионов, часовые пояса, ограничения на длину полей — их удобно запрашивать перед массовой загрузкой.

## Регулярные задачи

Если MCP-клиент умеет расписание (в Claude Code — `/schedule`), сценарии вешаются на автозапуск:

- утренняя сводка расхода за вчера с отклонениями от средних;
- еженедельный разбор поисковых запросов с предложением минус-слов;
- оповещение, если дневной расход кампании превысил порог.

## Осторожность

Изменяющие методы применяются к живому аккаунту сразу — «черновика» и отката в API нет.

- Перед пакетной правкой полезно попросить агента показать список изменений и, если нужно, сохранить текущие значения в файл.
- Для аналитики без риска: `YANDEX_DIRECT_READONLY=1` — сервер отклонит любой изменяющий метод.
- Права токена ограничены аккаунтом, под которым он выдан. Нужен другой аккаунт — нужен другой токен.
