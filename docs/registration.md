# Регистрация приложения и заявка на доступ к API

Самая долгая часть подключения. Пока заявка не одобрена, API не отвечает — ни боевой, ни песочница.

## Шаг 1. Приложение на Яндекс OAuth

Открой [oauth.yandex.ru](https://oauth.yandex.ru) → «Создать приложение».

| Поле | Значение |
|---|---|
| Платформа | Веб-сервисы |
| Redirect URI | `https://oauth.yandex.ru/verification_code` |
| Доступы | Яндекс Директ → «Использование API Яндекс Директа» |

После создания в карточке приложения появятся **ClientID** и **Client secret**.

- **ClientID** понадобится дальше — он не секретный.
- **Client secret** в этой схеме не используется вообще: токен получаем implicit-флоу (`response_type=token`). Не копируй его никуда и не вставляй в переписку с агентом.

**Не удаляй это приложение после одобрения заявки.** Одобрение привязано к ClientID, а не к аккаунту: удалишь приложение — придётся подавать заявку заново на новый ClientID.

## Шаг 2. Заявка на доступ к API

Подаётся в интерфейсе Директа: [«Мои заявки»](https://direct.yandex.ru/registered/main.pl?cmd=apiCertificationRequestList).

Кто подаёт: разработчик приложения, со своего логина. Одна заявка на приложение, независимо от числа пользователей. Пользователям готового приложения отдельно регистрироваться не нужно.

Сроки: рабочие дни РФ с 10:00 до 19:00, от часа до трёх суток, в пиковые периоды до семи дней.

### Технические данные о приложении

| Поле | Что писать |
|---|---|
| Язык программирования | `JavaScript (Node.js)` |
| Протокол | **JSON** (SOAP не используется) |
| Версия библиотек | `Node.js 18+, без сторонних SDK — прямые HTTPS-запросы к API v5` |

### Логины в Директе

Логин или логины аккаунтов, для которых приложение будет использоваться. Указывай те, где действительно есть кампании.

### Для чего предназначено приложение

- ✅ Автоматизировать регулярную работу по управлению кампаниями в Директе
- ✅ Синхронизировать рекламно-информационные материалы с данными внутренних систем — **только если** реально планируется подтягивать товары или остатки

### Основные функции приложения

- ✅ Получение статистики и отчетов
- ✅ Управление кампаниями и объявлениями
- ✅ Управление ставками (биддинг)
- Подбор ключевых слов (wordstat) — если планируешь собирать семантику

Отмечай только то, что действительно будешь делать: расширить доступ потом проще, чем объяснять незаявленную активность.

### «Какие новые возможности работы с Директом даёт ваше приложение пользователям»

> Приложение связывает рекламный аккаунт с AI-ассистентом в рабочей среде специалиста: задача ставится обычным текстом, приложение переводит её в вызовы API v5 и возвращает результат.
>
> Что это даёт пользователю:
>
> 1. Отчётность по запросу вместо ручных выгрузок. Статистика по кампаниям, группам, объявлениям, ключевым фразам и поисковым запросам за произвольный период собирается за один шаг и сразу приводится к нужному виду — доля расхода, CPC, CTR, конверсии, сравнение с предыдущим периодом.
>
> 2. Регулярные операции пакетно и по правилу, а не поштучно. Корректировка ставок и дневных бюджетов, запуск и остановка кампаний, отключение неэффективных фраз, добавление минус-слов по результатам отчёта по поисковым запросам — на основании только что полученной статистики, без ручного переноса данных между отчётом и интерфейсом.
>
> 3. Связь рекламы с внутренними данными: сверка объявлений с ассортиментом и наличием товара, остановка показов по позициям, которых нет в продаже.
>
> 4. Контроль над изменениями. Приложение работает от имени владельца аккаунта, каждое изменяющее действие выполняется только по явному подтверждению оператора, предусмотрен режим «только чтение», в котором доступны исключительно методы получения данных и отчёты.

Пункт 3 убери, если синхронизацию с внутренними системами не планируешь.

### «Опишите схему взаимодействия вашего приложения с Директом»

К этому полю прикладывается схема — готовая картинка лежит в [scheme.png](scheme.png), исходник в [scheme.html](scheme.html).

> Приложение работает локально на компьютере оператора. Собственных серверов, облачных компонентов и промежуточных сервисов нет, данные рекламного аккаунта в сторонние системы не передаются.
>
> 1. Авторизация. Пользователь один раз самостоятельно выдаёт приложению OAuth-токен через Яндекс OAuth (scope «Использование API Яндекс Директа»). Токен сохраняется на компьютере оператора в файле с правами доступа 600. Пользователь может отозвать его в любой момент.
>
> 2. Постановка задачи. Оператор формулирует задачу обычным текстом AI-ассистенту, работающему в его среде разработки. Ассистент определяет, какие именно вызовы API нужны, и обращается к модулю приложения.
>
> 3. Запрос к API. Модуль приложения формирует HTTPS-запрос POST на `https://api.direct.yandex.com/json/v5/{service}` с заголовком `Authorization: Bearer <OAuth-токен>` и телом `{"method": …, "params": …}`. Используются сервисы campaigns, adgroups, ads, keywords, bids, dictionaries и reports. Изменяющие методы (add, update, delete, suspend, resume) выполняются пооперационно и только после явного подтверждения оператора; предусмотрен режим «только чтение», в котором такие методы блокируются на уровне приложения.
>
> 4. Обработка ответа. Приложение получает JSON-результат, а для отчётов — TSV; при кодах 201 и 202 запрос отчёта повторяется до готовности с учётом заголовка retryIn. Соблюдается постраничная выборка через LimitOffset, расход баллов контролируется по заголовку Units в каждом ответе.
>
> 5. Возврат результата. Ассистент разбирает ответ и показывает оператору сводку. Результаты остаются на компьютере оператора.

Если есть поле про частоту обращений — пиши как есть: единичные запросы по инициативе оператора, без фонового опроса и без расписания.

## Шаг 3. Токен

После одобрения — и только после — получай токен:

```bash
./save-token.sh <CLIENT_ID>
```

Сверь ClientID с тем, что указан в **одобренной** заявке. Токен под другим приложением даст ошибку 58, даже если заявка одобрена: именно на этом мы потеряли больше всего времени.

## Если что-то пошло не так

**Ошибка 58 при одобренной заявке.** Открой заявку и сверь ClientID. Если приложений несколько, легко получить токен не под тем.

**Повторная авторизация возвращает прежний токен.** Так и работает Яндекс OAuth: пока доступ приложению не отозван, выдаётся уже существующий токен. Отзови доступ на [id.yandex.ru/personal/data-access](https://id.yandex.ru/personal/data-access) и авторизуйся заново.

**Приложение удалено вместе с одобрением.** Создавай новое и подавай заявку заново, указав в описании прежний ClientID и то, что приложение пересоздано.

**Нужен другой рекламный аккаунт.** Просто получи токен, авторизовавшись нужным логином. Заявка одобрена на приложение, а не на пользователя — повторно подавать её не нужно.
